## User Scenarios & Testing *(mandatory)*

### User Story 1 - 기존 문서가 폴더 안으로 옮겨져 계속 열림 (Priority: P1)

M1·M2에서 쓰던 문서 1개는 저장 방식이 바뀐 뒤에도 그대로 남아야 합니다. 작성자가 업데이트 후 처음
화면을 열면, 기존 문서가 사이드바의 기본 폴더 "내 문서" 안에 "제목 없는 문서"로 보이고 편집 영역에
열려 있습니다. [저장]은 이 문서를 갱신합니다.

**Why this priority**: 저장 방식을 바꾸면서 기존 문서를 잃으면 안 됩니다. 다른 모든 스토리가 이 저장소
위에서 동작합니다.

**Independent Test**: M2 버전에서 문서를 저장한 브라우저로 새 버전을 열어, 같은 본문이 "내 문서 /
제목 없는 문서"로 보이고 [저장]·새로고침 후에도 유지되는지 확인합니다.

**Acceptance Scenarios**:

1. **Given** 이전 버전 저장본이 있는 브라우저, **When** 새 버전을 처음 열면, **Then** 사이드바에 "내
   문서" 폴더와 그 안의 "제목 없는 문서"가 보이고, 편집 영역에 이전 저장본이 글자 하나 다르지 않게
   열립니다.
2. **Given** 이전 저장본이 없는 첫 방문, **When** 화면을 열면, **Then** "내 문서" 폴더에 샘플 문서
   1개("시작하기")가 만들어져 열립니다.
3. **Given** 문서를 연 상태, **When** 수정 후 [저장]을 누르면, **Then** 열린 문서가 갱신되고 새로고침
   후 같은 문서가 같은 내용으로 열립니다.
4. **Given** 옮기기를 마친 상태, **When** 다시 새로고침하면, **Then** 옮기기를 반복하지 않아 문서가
   2개로 늘지 않습니다.

### User Story 2 - 폴더 만들기와 트리 탐색 (Priority: P2)

작성자는 사이드바 상단 [+] 버튼으로 새 폴더를 만들고 이름을 정합니다. 사이드바에는 폴더와 그 안의
문서가 트리로 보이며, 폴더를 접고 펼 수 있습니다. 문서를 누르면 편집 영역에 열립니다.

**Why this priority**: 사이드바의 핵심 기능입니다(FR-2.1–2.3, 2.5).

**Independent Test**: [+]로 폴더 2개를 만들고, 접기·펼치기, 문서 클릭으로 열기를 확인합니다.

**Acceptance Scenarios**:

1. **Given** 사이드바, **When** [+]를 누르면, **Then** 목록 끝에 "새 폴더" 이름 입력 칸이 나타나고
   글자가 선택된 상태입니다. 이름을 입력하고 Enter를 누르면 폴더가 만들어집니다.
2. **Given** 이름 입력 중, **When** Esc를 누르거나 빈 이름으로 Enter를 누르면, **Then** 폴더가 만들어지지
   않습니다.
3. **Given** 폴더가 펼쳐진 상태, **When** 폴더 이름 줄을 누르면, **Then** 폴더가 접히고 다시 누르면
   펼쳐집니다. 접힘 상태는 새로고침 후에도 유지됩니다.
4. **Given** 다른 문서가 열린 상태, **When** 트리에서 문서를 누르면, **Then** 그 문서가 편집 영역에
   열리고 트리에서 현재 문서로 표시됩니다.
5. **Given** 열린 문서에 저장하지 않은 변경이 있음, **When** 다른 문서를 누르면, **Then** "저장하지 않은
   변경이 있습니다" 확인이 나오고 [저장 후 이동]·[버리고 이동]·[취소] 중에서 고릅니다.
6. **Given** 트리, **When** 키보드만 쓰면, **Then** 방향키로 항목 사이를 이동하고 Enter로 열거나
   접고 펼 수 있습니다.

### User Story 3 - 이름 바꾸기·삭제 (Priority: P3)

작성자는 폴더와 문서의 이름을 바꾸고, 필요 없는 항목을 지웁니다.

**Why this priority**: requirement.md FR-2.6 권장 항목입니다. 없어도 쓰는 데 지장은 없지만 잘못 만든
폴더를 정리할 수단이 필요합니다.

**Independent Test**: 폴더·문서 각각 이름 바꾸기와 삭제를 실행하고 새로고침 후 결과가 유지되는지
확인합니다.

**Acceptance Scenarios**:

1. **Given** 트리 항목, **When** 항목의 [⋯] 메뉴(또는 F2)에서 [이름 바꾸기]를 고르면, **Then** 이름이
   입력 칸으로 바뀌고 Enter로 확정, Esc로 취소됩니다.
2. **Given** 문서, **When** [⋯] → [삭제] → 확인을 누르면, **Then** 문서가 사라집니다. 열려 있던 문서면
   같은 폴더의 이름순 첫 문서(없으면 다른 폴더의 첫 문서, 그것도 없으면 빈 화면 안내)로 바뀝니다.
3. **Given** 문서 3개가 들어 있는 폴더 "회의", **When** [⋯] → [삭제]를 누르면, **Then** "'회의' 폴더를
   삭제할까요? 안의 문서 3개도 함께 삭제되며 되돌릴 수 없습니다" 확인이 나오고, [삭제]를 누르면 폴더와
   문서 3개가 사라집니다. 열린 문서가 그 안에 있었으면 시나리오 2의 규칙으로 다른 문서를 엽니다.
4. **Given** 빈 폴더, **When** [⋯] → [삭제]를 누르면, **Then** 문서 개수 문구 없이 같은 확인 후
   삭제됩니다.

---

### User Story 4 - 폴더 안에 새 문서 만들기 (Priority: P2)

작성자는 폴더의 [⋯] 메뉴에서 [새 문서]를 골라 그 폴더에 빈 문서를 만들고 바로 이름을 정해 씁니다.

**Why this priority**: 이것이 없으면 M3에서 문서는 기존 1개뿐이라 트리·열기·이름 바꾸기·삭제를 실제로
쓸 수 없습니다. 상단에서 폴더를 고르고 저장하는 흐름(FR-3)은 M6에서 따로 만듭니다.

**Independent Test**: 폴더 2개에 문서를 2개씩 만들고, 트리 표시·열기·새로고침 후 유지를 확인합니다.

**Acceptance Scenarios**:

1. **Given** 폴더 "회의", **When** [⋯] → [새 문서]를 누르면, **Then** 폴더가 펼쳐지고 그 안에 "제목 없는
   문서" 이름 입력 칸이 글자가 선택된 상태로 나타납니다. Enter로 확정하면 빈 문서가 만들어져 편집 영역에
   열립니다.
2. **Given** 이름 입력 중, **When** Esc를 누르면, **Then** 문서가 만들어지지 않습니다.
3. **Given** 같은 폴더에 "제목 없는 문서"가 이미 있음, **When** [새 문서]를 누르면, **Then** 입력 칸 기본
   이름이 "제목 없는 문서 2"입니다(비어 있는 가장 작은 번호).
4. **Given** 열린 문서에 저장하지 않은 변경이 있음, **When** [새 문서]를 확정하면, **Then** FR-010 확인을
   먼저 거칩니다.

---

### Edge Cases

- 같은 이름 폴더: 허용하지 않습니다. 같은 이름을 입력하면 입력 칸 아래에 "같은 이름의 폴더가 있습니다"를
  표시하고 확정하지 않습니다(앞뒤 공백을 지운 뒤 비교, 대소문자 구분 안 함).
- 같은 폴더 안 같은 이름 문서: 같은 규칙으로 막습니다(requirement.md FR-3.4는 M6에서 자동 접미사로
  다시 다룹니다).
- 이름 길이: 1–50자(눈에 보이는 글자 기준, M1 문자 수 규칙과 같음). 50자를 넘는 입력은 받지 않습니다. `/`·`\` 문자는 쓸 수 없습니다.
- 마지막 문서·폴더를 모두 지운 경우: 편집 영역에 "문서를 선택하거나 새로 만드십시오" 안내를 보이고
  [저장]·[취소]·툴바를 비활성으로 둡니다.
- 브라우저 저장소를 열 수 없는 경우(비공개 모드 제한 등): 화면 상단에 "브라우저 저장소를 쓸 수 없어
  변경 내용이 저장되지 않습니다" 안내를 고정 표시하고, 편집은 메모리에서만 동작합니다.
- 저장소 용량 초과로 저장 실패: M1과 같은 실패 알림을 띄우고 편집 내용은 유지합니다.
- 옮기기 도중 실패(새 저장소에 쓰기 실패): 이전 저장본을 지우지 않고 다음 열기에서 다시 시도합니다.
- 다른 탭에서 같은 문서를 수정: 마지막 저장이 이깁니다. 탭 간 실시간 동기화는 하지 않습니다.

## Requirements *(mandatory)*

### Functional Requirements

**저장소·옮기기**

- **FR-001**: 폴더와 문서를 브라우저 안의 구조화된 저장소에 영속 저장해야 합니다. 문서는 폴더 1개에
  속하고, 폴더는 문서 여러 개를 가집니다(requirement.md §6).
- **FR-002**: 처음 열 때 이전 버전 저장본(문서 1개)이 있으면 "내 문서" 폴더의 "제목 없는 문서"로 옮겨야
  합니다. 옮기기는 한 번만 일어나야 하며, 옮긴 뒤 이전 저장본은 지웁니다. 옮기기에 실패하면 이전
  저장본을 지우지 않습니다.
- **FR-003**: 저장본이 전혀 없는 첫 방문이면 "내 문서" 폴더와 샘플 문서 "시작하기"를 만들어야 합니다.
- **FR-004**: 마지막으로 열었던 문서를 기억해 다음 방문 때 그 문서를 열어야 합니다. 그 문서가 없으면
  트리의 첫 문서를 엽니다.
- **FR-005**: [저장]은 열린 문서의 본문과 수정 시각을 갱신해야 합니다. [취소]는 열린 문서의 마지막
  저장본으로 되돌립니다(M1 동작을 문서 단위로 유지).

**사이드바 트리**

- **FR-006**: 사이드바 상단에 [+] 폴더 만들기 버튼(접근 이름 "새 폴더")을 둬야 합니다.
- **FR-007**: 사이드바는 폴더를 이름순, 폴더 안 문서를 이름순으로 트리 표시해야 합니다. 정렬은 한국어
  사전순입니다.
- **FR-008**: 폴더는 접기·펼치기가 되고, 폴더별 접힘 상태는 새로고침 후에도 유지돼야 합니다.
- **FR-009**: 문서를 누르면 편집 영역에 열고, 열린 문서를 트리에서 시각적으로·보조기술로(선택된 항목)
  구분해야 합니다.
- **FR-010**: 열린 문서에 저장하지 않은 변경이 있을 때 다른 문서로 옮기려 하면 [저장 후 이동]·[버리고
  이동]·[취소] 확인을 보여야 합니다.
- **FR-011**: 트리는 키보드로 조작할 수 있어야 합니다 — ↑·↓ 항목 이동, →·← 폴더 펼치기·접기, Enter 열기,
  F2 이름 바꾸기, Delete 삭제(확인 포함).
- **FR-012**: 편집 영역 위(또는 상태바)에 열린 문서의 "폴더 / 문서 이름"을 표시해야 합니다.

**이름·삭제**

- **FR-013**: 폴더·문서 이름 바꾸기는 그 자리 입력 칸에서 Enter 확정, Esc·포커스 이탈 취소로 동작해야
  합니다. 이름 규칙은 Edge Cases를 따릅니다.
- **FR-014**: 삭제는 항목 이름을 포함한 확인("'회의록' 문서를 삭제할까요? 되돌릴 수 없습니다")을 거쳐야
  합니다. 삭제는 영구 삭제이며 휴지통은 없습니다.
- **FR-015**: 폴더 삭제는 안의 문서도 함께 영구 삭제합니다. 확인 문구에 함께 지워지는 문서 개수를
  표시해야 합니다(문서가 0개면 개수 문구 생략).

**새 문서**

- **FR-016**: 폴더 [⋯] 메뉴의 [새 문서]는 그 폴더에 빈 본문 문서를 만들어야 합니다. 기본 이름은 "제목 없는
  문서"이고, 같은 이름이 있으면 " 2", " 3"처럼 비어 있는 가장 작은 번호를 붙입니다. 만든 즉시 이름 입력
  상태가 되고, 확정하면 편집 영역에 엽니다. 저장하지 않은 변경이 있으면 FR-010 확인을 먼저 거칩니다.

### Key Entities

- **폴더(Folder)**: 이름(1–50자, 폴더끼리 중복 불가), 상위 폴더(이번 단계는 항상 없음 = 루트), 만든
  시각, 접힘 여부.
- **문서(Document)**: 소속 폴더, 제목(1–50자, 같은 폴더 안 중복 불가), 본문(마크다운), 만든 시각,
  수정 시각.
- **열린 문서 기억값**: 마지막으로 연 문서 1개의 식별값. 브라우저당 1개.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 이전 버전 저장본을 가진 브라우저에서 업데이트 후 본문이 글자 하나 다르지 않게 보존되는
  비율이 100%이고, 새로고침을 10번 해도 문서 수가 늘지 않습니다.
- **SC-002**: 폴더 만들기가 "[+] → 이름 입력 → Enter" 3단계 이하로 끝납니다.
- **SC-003**: 폴더 100개·문서 1,000개에서 화면을 열고 트리가 표시되기까지 1초 이하입니다.
- **SC-004**: 문서를 누르고 편집 영역에 열리기까지 1만 자 문서 기준 200ms 이하입니다.
- **SC-005**: 저장하지 않은 변경이 있을 때 확인 없이 다른 문서로 넘어가 변경이 사라지는 경로가
  0개입니다.
- **SC-006**: 마우스 없이 키보드만으로 폴더 만들기·문서 열기·이름 바꾸기·삭제를 모두 할 수 있습니다.
- **SC-007**: M1·M2 자동 테스트가 모두 통과합니다(저장 방식 교체로 바뀌는 기대값은 갱신분 명시).

## Assumptions

- **범위 근거**: requirement.md §12 M3 = 저장소 스키마·폴더 CRUD·[+] 버튼(FR-2 전체, FR-6 데이터).
  사이드바 폴더 메뉴의 [새 문서](US4)는 2026-11-12 결정으로 M3에 포함합니다. 상단 폴더 선택 후 저장
  흐름(FR-3), 대시보드 파일 리스트·주소 이동(FR-7.3·7.4)은 M6 범위입니다.
- **폴더 중첩 없음**: 이번 단계는 루트 폴더 1단계만 둡니다. 저장 구조는 상위 폴더 필드를 갖춰 나중에
  중첩으로 늘릴 수 있게 합니다(requirement.md §6).
