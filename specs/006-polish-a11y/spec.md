## User Scenarios & Testing *(mandatory)*

### User Story 1 - 저장하지 않고 탭을 닫으면 경고 (Priority: P1)

작성자가 문서를 고친 뒤 저장하지 않은 채 브라우저 탭을 닫거나, 새로고침하거나, 주소창에 다른 사이트 주소를
입력합니다. 브라우저가 "이 페이지를 나가시겠습니까?" 확인을 띄워 작성자가 머무를 수 있게 합니다
(requirement.md FR-7.7, PRD C-4).

**Why this priority**: M6의 저장 확인은 앱 안 이동만 막습니다. 탭을 닫으면 저장하지 않은 본문이 경고 없이
사라집니다. 데이터 손실을 막는 기능이라 접근성 점검보다 먼저입니다.

**Independent Test**: 문서 본문을 한 글자 고치고 새로고침하면 브라우저 확인이 뜹니다. 확인에서 머무르기를
고르면 고친 본문이 그대로 남아 있습니다.

**Acceptance Scenarios**:

1. **Given** 저장한 문서를 고쳐 저장하지 않은 상태, **When** 탭 닫기·새로고침·다른 사이트로 이동,
   **Then** 브라우저 이탈 확인이 뜹니다.
2. **Given** 1의 확인에서 머무르기 선택, **When** 화면을 봄, **Then** 고친 본문·폴더·제목이 그대로입니다.
3. **Given** 저장한 직후(고친 내용 없음), **When** 새로고침, **Then** 확인 없이 새로고침됩니다.
4. **Given** [새 문서] 초안에 본문을 한 글자 이상 입력, **When** 탭 닫기, **Then** 이탈 확인이 뜹니다.
5. **Given** [새 문서] 초안에 아무것도 입력하지 않음, **When** 탭 닫기, **Then** 확인 없이 닫힙니다.
6. **Given** 고친 뒤 [취소]로 저장 시점 내용으로 되돌림, **When** 새로고침, **Then** 확인 없이 새로고침됩니다.

---

### User Story 2 - 키보드만으로 모든 작업 (Priority: P2)

마우스를 쓰지 않는 작성자가 Tab·Shift+Tab·Enter·Space·방향키·Esc만으로 폴더 만들기, 문서 만들기, 쓰기,
서식 적용, 저장, 대시보드에서 문서 열기, 폴더·문서 삭제까지 끝냅니다. 포커스가 어디 있는지 항상 보입니다
(NFR-3 확장).

**Why this priority**: 각 마일스톤에서 부분별로 키보드 조작을 만들었지만, 화면 전체를 이어서 점검한 적이
없습니다. 화면을 바꾸거나 대화상자를 닫은 뒤 포커스가 사라지면 키보드 사용자는 작업을 이어 갈 수 없습니다.

**Independent Test**: 마우스를 쓰지 않고 SC-002의 작업 7개를 순서대로 끝냅니다.

**Acceptance Scenarios**:

1. **Given** 앱을 연 직후, **When** Tab을 누름, **Then** 포커스가 보이는 위치에서 시작하고 화면 위→아래,
   왼쪽→오른쪽 순서로 이동합니다.
2. **Given** 대화상자(저장 확인·삭제 확인·링크 입력 등)가 열림, **When** Tab 반복, **Then** 포커스가 대화상자
   밖으로 나가지 않습니다. Esc로 닫으면 입력 대화상자(링크·이미지 등)는 편집기로, 확인 대화상자는 대화상자를
   연 요소로 포커스가 돌아갑니다.
3. **Given** 앱 안에서 화면을 옮김(문서 열기·대시보드·새 문서·없는 문서), **When** 바뀐 직후, **Then** 포커스가
   새 화면의 정해진 시작점에 있습니다(FR-005). 앱을 처음 열 때는 포커스를 옮기지 않습니다.
4. **Given** 편집기 안에서 쓰는 중, **When** Tab을 누름, **Then** 포커스가 편집기 밖 다음 요소로 갑니다
   (FR-006).
5. **Given** 어떤 버튼·링크·입력 칸이든, **When** 키보드 포커스를 받음, **Then** 포커스 테두리가 보입니다.

---

### User Story 3 - 화면 낭독기로 상태 파악 (Priority: P3)

화면 낭독기 사용자가 각 영역(사이드바·문서 바·툴바·편집기·프리뷰·상태 표시줄)의 이름을 듣고, 저장 결과와
오류를 화면을 보지 않고 알 수 있습니다.

**Why this priority**: 알림 영역과 대부분의 이름은 이미 있습니다. 이 단계는 빠진 이름과 알림을 채우는
점검 작업입니다.

**Independent Test**: 접근성 트리를 검사해 이름 없는 상호작용 요소가 0개인지 확인합니다. 저장 버튼을 눌러
알림 문구가 낭독 대상 영역에 들어가는지 확인합니다.

**Acceptance Scenarios**:

1. **Given** 화면의 모든 버튼·링크·입력 칸·트리 항목, **When** 접근성 트리를 검사, **Then** 모두 한글 이름이
   있습니다.
2. **Given** 저장 성공·실패·폴더 미선택 오류, **When** 발생, **Then** 낭독기가 알림 문구를 읽습니다.
3. **Given** 툴바의 켜짐/꺼짐 버튼(굵게 등), **When** 커서가 굵은 글자 안에 있음, **Then** 버튼이 "눌림"
   상태로 읽힙니다.
4. **Given** 현재 열린 문서, **When** 사이드바 트리를 낭독, **Then** 그 항목이 "선택됨"으로 읽힙니다.

---

### Edge Cases

- 저장이 진행 중일 때 탭을 닫으면 이탈 확인이 뜹니다(저장 완료 전까지는 저장하지 않은 상태로 봅니다).
- 저장소를 열 수 없어 임시 저장소로 동작할 때는 고친 내용이 없어도 새로고침하면 문서가 사라집니다. 이 때는
  M3 안내 문구를 그대로 쓰고, 이탈 확인 규칙은 같습니다.
- 브라우저는 이탈 확인 문구를 직접 정하게 두지 않습니다. 확인 창 문구는 브라우저 기본 문구입니다.
- 이탈 확인을 거친 뒤 사용자가 떠나기를 고르면 저장하지 않은 내용은 사라집니다(자동 저장 없음).
- 앱 안 이동(사이드바·대시보드·뒤로/앞으로)은 M6 저장 확인 3버튼이 처리하고, 브라우저 이탈 확인이 겹쳐
  뜨지 않습니다.
- 운영체제의 "동작 줄이기" 설정과 상관없이 장식 모션은 원래 없습니다(헌장 원칙 VI).

## Requirements *(mandatory)*

### Functional Requirements

**이탈 경고 (US1)**

- **FR-001**: 열린 문서에 저장하지 않은 변경이 있으면, 탭 닫기·새로고침·다른 사이트로 이동할 때 브라우저
  이탈 확인을 띄워야 합니다.
- **FR-002**: "저장하지 않은 변경"은 저장된 문서면 본문·폴더·제목 중 하나라도 저장 시점과 다를 때, 초안이면
  본문을 입력했거나 제목을 기본값("제목 없는 문서")에서 바꿨을 때입니다. 초안에서 폴더만 고른 것은 변경이
  아닙니다. 이탈 경고와 M6 앱 안 저장 확인은 같은 기준을 써야 합니다. [취소]는 본문·폴더·제목을 모두 저장
  시점으로 되돌립니다.
- **FR-003**: 앱 안 이동은 M6 저장 확인만 띄우고 브라우저 이탈 확인을 띄우지 않아야 합니다.

**키보드 (US2)**

- **FR-004**: 모든 상호작용 요소는 키보드로 포커스를 받고 실행할 수 있어야 합니다. 포커스 순서는 화면에
  보이는 순서와 같아야 합니다.
- **FR-005**: 앱 안에서 화면을 옮기면 포커스를 다음 위치로 옮겨야 합니다. 앱을 처음 열 때는 옮기지 않습니다.

  | 바뀐 화면 | 포커스 위치 |
  |-----------|-------------|
  | 문서 열기 | 편집기 |
  | 새 문서 | 편집기 (M6 US1-1 유지) |
  | 대시보드 | 대시보드 제목 |
  | 없는 문서 | 안내 문구 |

- **FR-006**: 편집기 안에서 Tab·Shift+Tab을 누르면 편집기 밖 다음·이전 요소로 나가야 합니다. 편집기가
  키보드 포커스를 가두면 안 됩니다. 들여쓰기는 공백 입력과 목록 툴바 버튼으로 합니다.
- **FR-007**: 화면 맨 앞에 "본문으로 건너뛰기" 버튼을 두어야 합니다. 첫 Tab에서 보이고, 실행하면 포커스가
  FR-005 표와 같은 위치(편집기·대시보드 제목·없는 문서 안내 문구)로 옮겨집니다. 주소의 해시를 바꾸지 않아야
  합니다(M6 해시 주소와 충돌 방지).
- **FR-008**: 키보드로 포커스를 받는 모든 상호작용 요소(버튼·링크·입력 칸·편집기·트리 항목)는 액센트색
  포커스 테두리가 보여야 합니다. 상호작용 요소에 포커스 테두리를 지우는 스타일이 없어야 합니다. 스크립트로만
  포커스를 받는 비상호작용 요소(`tabIndex=-1`인 제목·안내 문구)는 예외입니다.

**화면 낭독기 (US3)**

- **FR-009**: 모든 버튼·링크·입력 칸·트리 항목은 접근 가능한 한글 이름을 가져야 합니다. 아이콘만 있는
  버튼도 예외가 없습니다.
- **FR-010**: 화면 영역(사이드바·주 이동·편집 영역·문서 바·툴바·편집기·프리뷰·상태 표시줄)은 낭독기의 영역
  이동으로 찾을 수 있게 이름이 있는 영역이어야 합니다. 대시보드는 편집 영역 안에 그려지므로 별도 영역 대신
  제목("모든 문서")으로 찾습니다.
- **FR-011**: 저장 결과 알림과 입력 오류는 낭독기가 읽어야 합니다.
- **FR-012**: 켜짐/꺼짐이 있는 툴바 버튼은 눌림 상태를, 사이드바에서 열린 문서는 선택 상태를 낭독기에
  전달해야 합니다.

**색 대비**

- **FR-013**: 본문 글자는 배경 대비 4.5:1 이상, 큰 글자(18.66px 굵게 또는 24px 이상)·아이콘·포커스 테두리·
  입력 칸 테두리는 3:1 이상이어야 합니다. 기준에 못 미치는 색은 디자인 시안 색에 가장 가까운 통과 색으로
  바꿉니다.

**범위 결정**

- **FR-014**: 모바일 화면 지원(NFR-4 에디터/프리뷰 탭 전환)은 이번 범위에서 뺍니다. 데스크톱 전용입니다.
- **FR-015**: `.md` 파일 내보내기(PRD C-5)는 이번 범위에서 뺍니다.

### Key Entities

저장 데이터는 바뀌지 않습니다. "저장하지 않은 변경" 판단 기준을 FR-002로 새로 정의하고, 이탈 경고와 M6 앱 안
저장 확인이 같은 기준을 씁니다([data-model.md](./data-model.md)).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: US1 수용 시나리오 6개에서 이탈 확인이 뜨는지 여부가 모두 기대와 일치합니다(6/6).
- **SC-002**: 마우스 없이 다음 작업 7개를 모두 끝낼 수 있습니다 — 폴더 만들기, 사이드바에서 새 문서 만들기,
  본문 쓰고 굵게 적용, 링크 대화상자로 링크 넣기, 저장, 대시보드에서 다른 문서 열기, 폴더 삭제.
- **SC-003**: 자동 접근성 검사에서 이름 없는 상호작용 요소가 0개입니다.
- **SC-004**: 화면 전환 4종(FR-005)과 대화상자 닫기 후 포커스 위치가 기대와 모두 일치합니다.
- **SC-005**: 화면에 쓰인 글자·테두리 색 조합이 FR-013 대비 기준을 100% 통과합니다.
- **SC-006**: 기존 M1–M6 자동 테스트가 모두 통과합니다(회귀 0건).

## Assumptions

- 접근성 기준은 WCAG 2.2 AA를 따릅니다. 범위는 이 앱의 화면 전체입니다.
- 화면 낭독기 수동 확인은 macOS VoiceOver + Chrome 1종으로 합니다.
- 이탈 확인 문구는 브라우저가 정합니다(사용자 지정 문구 불가).
- 자동 저장은 이번 범위가 아닙니다. 이탈 확인에서 떠나기를 고르면 저장하지 않은 내용은 사라집니다.
- 편집기 Tab 동작: 지금 편집기는 Tab을 들여쓰기로 쓰지 않아 Tab이 포커스를 옮깁니다. 이 동작을 유지합니다
  (research R3).
- 프리뷰는 읽기 전용이라 포커스 순서에서 영역 하나로만 다룹니다.
