## User Scenarios & Testing *(mandatory)*

### User Story 1 - 입력하면서 프리뷰 확인 (Priority: P1)

작성자는 화면 왼쪽 편집 영역에 마크다운을 입력합니다. 오른쪽 프리뷰 영역에는 입력 결과가
렌더된 문서로 곧바로 표시됩니다. 작성자는 문법을 외우거나 결과를 추측하지 않고 최종 모양을
확인하며 씁니다.

**Why this priority**: 제품의 핵심 가치(입력 즉시 정확한 프리뷰)입니다. 이 기능만으로도
"써 보고 결과를 확인하는" 도구로 쓸 수 있습니다.

**Independent Test**: 빈 편집 영역에 제목·목록·표·코드 블록을 입력하고, 프리뷰에 각 요소가
명세대로 렌더되는지 확인합니다.

**Acceptance Scenarios**:

1. **Given** 첫 방문으로 저장본이 없는 상태, **When** 화면을 열면, **Then** 편집 영역에
   샘플 문서가 표시되고 프리뷰에 그 렌더 결과가 함께 표시됩니다.
2. **Given** 편집 영역에 문서가 있는 상태, **When** `# 제목`을 입력하면, **Then** 입력을
   멈춘 뒤 150ms 안에 프리뷰에 1단계 제목이 표시됩니다.
3. **Given** 편집 영역, **When** 표·취소선·작업목록 문법을 입력하면, **Then** 프리뷰에
   표·취소선·체크박스가 렌더됩니다.
4. **Given** 편집 영역, **When** `<script>alert(1)</script>` 또는 `<img src=x onerror=...>`를
   입력하면, **Then** 스크립트가 실행되지 않고 위험한 속성이 프리뷰에서 제거됩니다.
5. **Given** 편집 영역, **When** 문서를 수정하면, **Then** 하단 상태바의 문자 수와 줄 수가
   수정 결과에 맞게 바뀝니다.

---

### User Story 2 - 저장하고 다시 열기 (Priority: P2)

작성자는 [저장]을 눌러 문서를 브라우저에 보관합니다. 새로고침하거나 나중에 다시 방문해도
마지막으로 저장한 문서가 그대로 열립니다. 저장 이후의 수정이 마음에 들지 않으면 [취소]로
마지막 저장 상태로 되돌립니다.

**Why this priority**: 저장이 없으면 작성한 내용이 새로고침 한 번에 사라집니다. 계정·서버
없이 문서를 보존하는 것이 두 번째 핵심 가치입니다.

**Independent Test**: 문서를 수정하고 저장한 뒤 새로고침해 수정본이 열리는지 확인합니다.
다시 수정하고 [취소]를 눌러 저장본으로 돌아가는지 확인합니다.

**Acceptance Scenarios**:

1. **Given** 문서를 수정한 상태, **When** [저장]을 누르면, **Then** "저장되었습니다" 알림이
   1,900ms간 표시됩니다.
2. **Given** 저장을 마친 상태, **When** 페이지를 새로고침하면, **Then** 마지막 저장본이
   편집 영역과 프리뷰에 표시됩니다.
3. **Given** 저장 후 다시 수정한 상태, **When** [취소]를 누르면, **Then** 편집 영역이 마지막
   저장본으로 돌아가고 "마지막 저장 상태로 되돌렸습니다" 알림이 표시됩니다.
4. **Given** 한 번도 저장하지 않은 상태, **When** [취소]를 누르면, **Then** 편집 영역이 샘플
   문서로 돌아갑니다.
5. **Given** 브라우저 저장소에 쓸 수 없는 상태(용량 초과, 비공개 모드 차단), **When**
   [저장]을 누르면, **Then** 저장 실패 알림이 표시되고 편집 중인 내용은 그대로 남습니다.

---

### User Story 3 - 툴바로 서식 적용 (Priority: P3)

작성자는 상단 툴바 버튼을 눌러 문법을 외우지 않고 서식을 넣습니다. 텍스트를 선택한 상태면
선택 영역에 서식이 적용되고, 선택이 없으면 자리표시 텍스트가 들어간 뒤 그 텍스트가 선택돼
바로 덮어쓸 수 있습니다.

**Why this priority**: 문법을 아는 사용자는 툴바 없이도 작성할 수 있으므로 P1·P2보다
뒤입니다. 디자인 시안의 단일 화면을 완성하는 마지막 조각입니다.

**Independent Test**: 툴바 버튼 12개를 각각 선택 있음/없음 두 상태에서 눌러, 편집 영역에
들어간 문법과 선택 범위가 아래 FR-010 표와 일치하는지 확인합니다.

**Acceptance Scenarios**:

1. **Given** "강조"를 선택한 상태, **When** [굵게]를 누르면, **Then** 텍스트가 `**강조**`로
   바뀌고 "강조"가 선택된 상태로 남습니다.
2. **Given** 선택이 없는 상태, **When** [굵게]를 누르면, **Then** 커서 위치에 자리표시
   텍스트를 감싼 `**…**`가 들어가고 자리표시 텍스트가 선택됩니다.
3. **Given** 여러 줄을 선택한 상태, **When** [글머리 목록]을 누르면, **Then** 선택한 모든
   줄 앞에 `- `가 붙습니다.
4. **Given** "문서"를 선택한 상태, **When** [링크]를 누르면, **Then** `[문서](https://)`가
   들어가고 URL 자리(`https://`)가 선택돼 바로 주소를 입력할 수 있습니다.
5. **Given** 툴바, **When** 키보드 Tab으로 이동하면, **Then** 버튼 12개가 차례로 포커스되고
   각 버튼의 한글 이름이 보조기술로 읽힙니다.

### Edge Cases

- 빈 문서: 프리뷰가 빈 상태로 표시되고 상태바는 `0자 | 1줄`을 표시합니다.
- 이모지·결합 문자: `한글👍é`는 `4자`로 표시합니다(FR-008).
- 1만 자 문서: 입력 중 글자가 늦게 나타나는 지연이 없어야 합니다(SC-003).
- 한글 조합 입력 중: 조합이 끝나기 전에 글자가 중복되거나 사라지지 않아야 합니다.
- 저장본이 빈 문자열: 빈 문서도 유효한 저장본이므로 샘플 문서 대신 빈 문서를 엽니다.
- 툴바 버튼을 연달아 누름: 매번 현재 커서·선택 기준으로 문법이 들어갑니다. 같은 서식을 다시
  눌렀을 때 해제(토글)는 이 기능 범위가 아닙니다(M5).
- 원시 HTML: `<kbd>Ctrl</kbd>`는 키 표시로 렌더되고, `<iframe>`·`<style>`처럼 허용 목록에
  없는 태그는 프리뷰에서 제거됩니다(FR-007).

## Requirements *(mandatory)*

### Functional Requirements

**화면 구성**

- **FR-001**: 화면은 상단 바(앱 이름 "Markdown Editor" + 툴바), 본문(편집 영역 50% : 프리뷰
  50%), 하단 상태바(문자 수·줄 수 + [취소]·[저장])로 구성해야 합니다.
- **FR-002**: 화면 시각(색·글꼴·간격)은 `docs/design/project/Markdown Editor.dc.html`과
  일치해야 합니다. 단, 헌장 원칙 VI이 금지하는 요소(로고의 그라데이션, 알림의 짙은 그림자,
  알림 등장 애니메이션)는 단색·무효과로 바꿉니다.

**편집과 프리뷰**

- **FR-003**: 편집 영역은 일반 텍스트 입력을 받으며 한글 조합 입력을 정상 처리해야 합니다.
- **FR-004**: 프리뷰는 입력이 멈춘 뒤 150ms 안에 갱신돼야 합니다.
- **FR-005**: 프리뷰는 CommonMark 0.31.2 코어 문법을 `docs/markdown-editor-spec.md`의
  HTML 결과물과 같은 구조로 렌더해야 합니다.
- **FR-006**: 프리뷰는 GFM 확장 4종(표, 취소선, 작업목록, 자동링크 리터럴)을 렌더해야 합니다.
- **FR-007**: 프리뷰는 렌더 전에 원시 HTML을 정제해야 합니다. GitHub 수준 허용 목록의
  안전한 태그(`<kbd>`, `<details>`, `<summary>`, `<sub>`, `<sup>` 등)는 렌더하고, 목록에 없는
  태그는 제거합니다. 스크립트 태그, 이벤트 핸들러 속성(`on*`), `javascript:` URL은 결과에
  남아서는 안 됩니다.
- **FR-008**: 상태바는 현재 문서의 문자 수와 줄 수를 `{n}자 | {n}줄` 형식으로 표시해야
  합니다.
  - 문자 수는 눈에 보이는 글자 단위로 세며 공백·줄바꿈을 포함합니다. 이모지(`👍`)와 결합
    문자(`é` = e + 결합 부호)는 1자입니다.
  - 줄 수는 줄바꿈 수 + 1입니다.
  - 두 값 모두 1,000 이상이면 천 단위 쉼표를 붙입니다(`12,345자`).

**툴바**

- **FR-009**: 툴바 버튼 12개는 모두 한글 접근 이름을 가지며 키보드로 포커스하고 실행할 수
  있어야 합니다.
- **FR-010**: 각 버튼은 아래 표대로 동작해야 합니다. 적용 후 편집 영역에 포커스가 돌아와야
  합니다.

  | 버튼 | 동작 | 선택 없을 때 |
  |------|------|-------------|
  | 제목 | 현재 줄들 앞에 `## ` | 현재 줄에 적용 |
  | 굵게 | 선택을 `**`로 감쌈 | 자리표시 텍스트를 감싸고 선택 |
  | 기울임 | 선택을 `*`로 감쌈 | 같음 |
  | 취소선 | 선택을 `~~`로 감쌈 | 같음 |
  | 인용 | 현재 줄들 앞에 `> ` | 현재 줄에 적용 |
  | 인라인 코드 | 선택을 `` ` ``로 감쌈 | 자리표시 텍스트를 감싸고 선택 |
  | 코드 블록 | 선택을 ```` ``` ```` 펜스 블록으로 감쌈 | 본문이 "코드"인 펜스 블록 삽입 |
  | 링크 | `[선택](https://)` 삽입, URL 부분 선택 | 텍스트 자리에 "링크 텍스트" |
  | 글머리 목록 | 현재 줄들 앞에 `- ` | 현재 줄에 적용 |
  | 번호 목록 | 현재 줄들 앞에 `1. ` | 현재 줄에 적용 |
  | 표 | 커서 위치에 2열 표 견본 삽입 | 같음 |
  | 구분선 | 커서 위치에 `---` 줄 삽입 | 같음 |

**저장**

- **FR-011**: [저장]은 현재 문서 전체를 브라우저 로컬 저장소에 보관해야 합니다. 저장하는
  문서는 1개이며 다음 저장이 이전 저장본을 덮어씁니다.
- **FR-012**: 화면을 열 때 저장본이 있으면 저장본을, 없으면 샘플 문서를 표시해야 합니다.
- **FR-013**: [취소]는 편집 내용을 마지막 저장본(저장한 적이 없으면 샘플 문서)으로
  되돌려야 합니다.
- **FR-014**: 저장 성공, 저장 실패, 취소 각각에 서로 다른 알림 문구를 1,900ms간 표시해야
  합니다. 성공과 실패는 문구와 아이콘으로 구분합니다.
- **FR-015**: 저장소 읽기에 실패하면 샘플 문서로 시작하고 화면이 멈추지 않아야 합니다.

**배포**

- **FR-016**: 앱은 서버 없이 정적 호스팅으로 배포·실행돼야 합니다.

### Key Entities

- **문서(Document)**: 작성 중인 마크다운 원문 1개. 속성은 본문 텍스트뿐이며 제목·폴더·
  작성일은 없습니다(M3에서 추가).
- **저장본(Saved Snapshot)**: 마지막으로 [저장]한 시점의 문서 본문. [취소]의 복원 대상이며
  브라우저에 1개만 존재합니다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 입력을 멈춘 뒤 프리뷰 갱신까지 150ms 이하입니다.
- **SC-002**: `docs/markdown-editor-spec.md`의 코어 기능 예제와 GFM 확장 4종 예제 전부에서
  프리뷰 출력이 기대 HTML과 일치합니다.
- **SC-003**: 1만 자 문서에서 키 입력부터 글자 표시까지 50ms를 넘는 입력이 0건입니다.
- **SC-004**: XSS 견본 입력 10종(스크립트 태그, `on*` 속성, `javascript:` 링크 포함)에서
  스크립트 실행이 0건입니다.
- **SC-005**: 저장 후 새로고침했을 때 본문이 한 글자도 다르지 않게 복원되는 비율이
  100%입니다.
- **SC-006**: 마우스 없이 키보드만으로 툴바 버튼 12개와 [취소]·[저장]을 모두 실행할 수
  있습니다.
- **SC-007**: 첫 방문 사용자가 설명 없이 문서를 수정하고 저장하는 데 1분 이내가 걸립니다.

## Assumptions

- **M1 범위 해석**: `docs/requirement.md §12`는 M1을 "프로젝트 스캐폴딩"으로만 적었지만,
  `docs/PRD.md §3.1·§7`은 M1을 "단일 화면 1차 출시"로 정의합니다. 스캐폴딩만으로는 사용자
  시나리오가 없으므로, 이 spec은 스캐폴딩 + 디자인 시안의 단일 화면 전체(M4 에디터·프리뷰,
  M7 일부 저장 피드백)를 M1로 묶습니다. 이 해석은 2026-11-12 Clarifications에서 확정했습니다.
- 툴바는 디자인 시안의 버튼 12개로 한정합니다. 나머지 태그(H1–H6 개별, 이미지, 작업목록
  등), 토글 해제, 단축키, 링크·이미지 입력 대화상자는 M5 범위입니다.
- 코드 블록 버튼은 시안처럼 선택 영역을 견본으로 덮어쓰지 않고 선택 영역을 감쌉니다. 시안
  방식은 선택한 텍스트를 지워 사용자 입력을 잃기 때문입니다.
- 링크는 대화상자 대신 시안대로 URL 자리를 선택한 상태로 삽입합니다(PRD B-4의 대화상자는
  M5에서 적용).
- 폴더·여러 문서·사이드바·대시보드는 범위 밖입니다(M2·M3·M6).
