# Feature Specification: 저장 시 `.md` 파일 쓰기 (resource/md)

**Feature Branch**: `008-md-file-export` (git 작업 브랜치: `feature/init`)

**Created**: 2026-11-13

**Status**: Draft

**Input**: "저장시 @resource/md 폴더 하위에 markdown 파일로 저장기능" — 결정(2026-11-13): 방식 A(브라우저 폴더 연결,
File System Access API), 앱 폴더 구조 유지. `docs/requirement.md` FR-7.5·PRD C-5(선택 항목)에 해당하며 M7에서 범위 밖으로
뒀던 항목을 이번에 넣습니다.

## 배경

앱은 서버 없이 브라우저에서만 동작합니다(헌장 원칙 V, `output: "export"`). 웹 페이지는 디스크의 정해진 경로에 마음대로 쓸 수
없으므로, 사용자가 `resource/md` 폴더를 한 번 골라 쓰기를 허락하고 앱이 그 폴더를 기억합니다. 문서 데이터의 원본은 계속
IndexedDB이고 `.md` 파일은 저장할 때 함께 쓰는 사본입니다.

## User Story — 저장하면 연결한 폴더에 `.md` 파일이 생김 (P1)

작성자는 상단 [저장 폴더 연결]로 `resource/md` 폴더를 고릅니다. 이후 [저장]을 누를 때마다 그 폴더 아래
`<앱 폴더 이름>/<문서 제목>.md` 파일이 만들어지거나 갱신됩니다.

**Acceptance Scenarios**:

1. **Given** 폴더 미연결, **When** [저장], **Then** 지금처럼 브라우저 저장소에만 저장되고 파일은 쓰지 않습니다.
2. **Given** [저장 폴더 연결] → `resource/md` 선택·허락, **When** 폴더 "회의"의 "주간 회의"를 [저장], **Then**
   `resource/md/회의/주간 회의.md`에 본문이 그대로 쓰이고, 알림에 파일 경로가 나옵니다.
3. **Given** 2 상태, **When** 본문을 고쳐 다시 [저장], **Then** 같은 파일이 새 본문으로 바뀝니다.
4. **Given** 2 상태, **When** 제목을 "주간 회의 2"로 바꾸거나 폴더를 "메모"로 옮겨 [저장], **Then** 새 경로에 파일을 쓰고
   이전 경로 파일(`회의/주간 회의.md`)은 지웁니다.
5. **Given** 브라우저를 다시 열어 쓰기 허락이 풀림, **When** [저장], **Then** 브라우저가 허락을 다시 묻고, 허락하면 씁니다.
   거절하면 브라우저 저장소 저장은 성공하고 "파일로 쓰지 못했습니다" 오류 알림이 뜹니다.
6. **Given** File System Access API가 없는 브라우저(Safari·Firefox), **When** 화면을 봄, **Then** [저장 폴더 연결] 버튼이
   보이지 않고 저장은 브라우저 저장소에만 합니다.

## Requirements

- **FR-001**: 상단 이동 영역에 [저장 폴더 연결] 버튼을 둡니다(`window.showDirectoryPicker`가 있을 때만). 연결 후에는 버튼
  글자가 연결한 폴더 이름(예: `md`)을 보여 주고, 다시 누르면 다른 폴더로 바꿉니다.
- **FR-002**: 연결한 폴더(directory handle)는 IndexedDB `meta`의 `exportDir`에 저장해 새로고침 뒤에도 유지합니다.
- **FR-003**: [저장]이 브라우저 저장소 저장에 성공하고 폴더가 연결돼 있으면 `<연결 폴더>/<앱 폴더 이름>/<제목>.md`에 본문을
  UTF-8로 씁니다. 하위 폴더가 없으면 만듭니다. 이미 있으면 덮어씁니다.
- **FR-004**: 이번 저장에서 제목이나 폴더가 바뀌었으면 이전 경로 파일을 지웁니다(빈 폴더는 남김).
- **FR-005**: 파일 이름·폴더 이름의 운영체제 금지 글자 `< > : " | ? *`와 제어 문자는 `_`로 바꾸고, 끝의 공백·마침표는
  지웁니다. 결과가 비거나 `.`·`..`이면 `_`입니다(앱 이름 규칙이 이미 `/`·`\`를 막음).
- **FR-006**: 파일 쓰기 실패(허락 거절·폴더 삭제됨 등)는 브라우저 저장소 저장을 되돌리지 않습니다. 오류 알림 모달로
  "저장은 됐지만 파일로 쓰지 못했습니다"를 알립니다.

## User Story 2 — 문서 1개 다운로드 (P1, 2026-11-14 추가)

작성자는 사이드바 문서 줄의 [다운로드] 버튼으로 그 문서를 `<제목>.md` 파일로 내려받습니다. 폴더 연결이 필요 없고 모든
브라우저에서 동작합니다. 결정(2026-11-14): 위치 = 사이드바 문서 줄 버튼, 내용 = 마지막으로 저장한 본문, 범위 = 문서 1개.

- **FR-007**: 사이드바 문서 줄 버튼을 [다운로드](`Download`) · [이름 바꾸기] · [삭제] 순서로 둡니다(007 FR-012 줄 버튼 확장).
  이름은 `‘제목’ 다운로드`, 폴더 줄에는 없습니다.
- **FR-008**: 다운로드 내용은 저장소에 마지막으로 저장된 본문입니다. 편집기의 저장하지 않은 수정은 들어가지 않습니다.
- **FR-009**: 파일 이름은 FR-005 규칙을 적용한 `<제목>.md`, 형식은 `text/markdown;charset=utf-8`입니다.
- **FR-010**: 버튼은 앱 화면 이동·저장 확인을 일으키지 않습니다(다운로드만).

## 범위 밖

- 앱에서 문서·폴더를 삭제하거나 사이드바에서 이름만 바꿀 때(저장 없이) 디스크 파일을 고치지 않습니다. 다음 [저장] 때 반영됩니다.
- 디스크의 `.md` 파일을 앱으로 가져오기(FR-7.5 "가져오기")는 하지 않습니다.

## Success Criteria

- **SC-001**: 경로 규칙·파일 쓰기·이전 파일 삭제·허락 거절을 가짜 디렉터리 핸들로 단위 테스트합니다.
- **SC-002**: production 빌드·기존 테스트 회귀 0건. 수동 검증(Chrome)에서 시나리오 1–6 확인.
