## User Scenarios & Testing *(mandatory)*

### User Story 1 - 모든 문법을 버튼으로 넣기 (Priority: P1)

작성자는 제목 단계(H1–H3), 이미지, 작업 목록, 강제 줄바꿈, 자동 링크를 포함한 18개 문법을 툴바
버튼으로 넣습니다. 문법을 외우지 않아도 명세 문서의 툴바 대상 문법을 모두 쓸 수 있습니다.

**Why this priority**: 사용자가 지적한 누락 사항입니다. 현재 12버튼으로는 H1·H3, 이미지, 작업 목록,
강제 줄바꿈, 자동 링크를 넣을 수 없습니다.

**Independent Test**: 18버튼을 선택 있음/없음 두 상태에서 각각 눌러, 편집 영역에 들어간 문법과 선택
범위가 FR-002 표와 일치하는지, 프리뷰에 해당 요소가 렌더되는지 확인합니다.

**Acceptance Scenarios**:

1. **Given** "제목"이 있는 줄에 커서, **When** [H1]을 누르면, **Then** 줄이 `# 제목`이 되고 프리뷰에
   1단계 제목이 보입니다. [H2]·[H3]도 각각 `## `·`### `를 넣습니다.
2. **Given** 두 줄을 선택, **When** [작업 목록]을 누르면, **Then** 두 줄 앞에 `- [ ] `가 붙고 프리뷰에
   체크박스 2개가 보입니다.
3. **Given** "https://example.com"을 선택, **When** [자동 링크]를 누르면, **Then**
   `<https://example.com>`이 되고 프리뷰에 링크가 보입니다.
4. **Given** "foo" 뒤에 커서, **When** [강제 줄바꿈]을 누르면, **Then** `foo\` 뒤에 줄바꿈이 들어가고
   커서가 다음 줄 맨 앞에 옵니다.
   *(2026-11-13 `specs/007-usability-fixes` FR-004로 대체: `foo` 뒤에 공백 2개 + 줄바꿈. 줄 접두 버튼의 커서 위치는
   같은 문서 FR-001)*
5. **Given** 여러 줄 선택, **When** [번호 목록]을 누르면, **Then** 줄마다 `1. `, `2. `, `3. `처럼 번호가
   1씩 늘어납니다.
6. **Given** 툴바, **When** 화면을 보면, **Then** 버튼 18개가 5개 묶음으로 나뉘어 보이고 H4–H6 버튼은
   없습니다.

### User Story 2 - 다시 누르면 해제, 적용 상태 표시 (Priority: P2)

작성자는 이미 굵게 처리한 텍스트를 다시 [굵게]로 누르면 서식이 풀립니다. 커서가 굵은 텍스트나 제목
줄 안에 있으면 해당 버튼이 눌린 상태로 보입니다.

**Why this priority**: 토글이 없으면 같은 버튼을 두 번 눌렀을 때 `****텍스트****`처럼 문법이 겹쳐
문서가 깨집니다. 지금 M1 툴바에서 실제로 일어나는 문제입니다.

**Independent Test**: 토글 대상 버튼마다 "적용 → 다시 누름"을 실행해 원문으로 돌아오는지, 커서
위치에 따라 버튼 눌림 표시가 바뀌는지 확인합니다.

**Acceptance Scenarios**:

1. **Given** `**강조**`에서 "강조"를 선택, **When** [굵게]를 누르면, **Then** `강조`가 되고 "강조"가
   선택된 상태로 남습니다.
2. **Given** `## 제목` 줄에 커서, **When** [H2]를 누르면, **Then** `제목`이 됩니다. [H1]을 누르면
   `# 제목`으로 단계만 바뀝니다.
3. **Given** `- 항목` 줄에 커서, **When** [번호 목록]을 누르면, **Then** `1. 항목`으로 목록 종류가
   바뀝니다. 같은 줄에서 [글머리 목록]을 누르면 `항목`으로 해제됩니다.
4. **Given** 커서가 `**강조**` 안에 있음, **When** 툴바를 보면, **Then** [굵게]가 눌린 상태로 보이고
   보조기술이 "눌림"으로 읽습니다. 커서를 밖으로 옮기면 눌림이 풀립니다.
5. **Given** `**강조**`에서 "강조" 선택, **When** [기울임]을 누르면, **Then** 굵게는 그대로 두고
   기울임을 더해 `***강조***`가 됩니다.
6. **Given** 선택 없이 커서가 `**강|조**`의 강과 조 사이에 있음(`|`=커서), **When** [굵게]를
   누르면, **Then** `강|조`가 되고 커서는 강과 조 사이에 남습니다.

### User Story 3 - 링크·이미지 입력 대화상자 (Priority: P3)

작성자는 [링크]나 [이미지]를 누르면 작은 입력 창에 주소(이미지는 대체 텍스트도)를 넣고 [삽입]을
누릅니다. 편집 영역에 완성된 문법이 들어갑니다.

**Why this priority**: 지금은 `[텍스트](https://)` 견본을 넣은 뒤 주소를 직접 고쳐야 합니다. 동작은
하므로 P1·P2보다 뒤입니다.

**Independent Test**: 선택 있음/없음에서 [링크]·[이미지] 대화상자를 열어 입력·삽입·취소하고, 결과
문법과 포커스 위치를 확인합니다.

**Acceptance Scenarios**:

1. **Given** "문서"를 선택, **When** [링크] → 주소 `https://a.com` 입력 → [삽입], **Then**
   `[문서](https://a.com)`이 들어가고 커서가 그 뒤에 옵니다.
2. **Given** 선택 없음, **When** [이미지] → 대체 텍스트 "로고", 주소 `/logo.png` → Enter, **Then**
   `![로고](/logo.png)`가 들어갑니다.
3. **Given** 대화상자가 열린 상태, **When** Esc를 누르거나 [취소]를 누르면, **Then** 문서는 바뀌지 않고
   포커스가 원래 선택 위치의 편집 영역으로 돌아갑니다.
4. **Given** 주소 칸이 비어 있음, **When** [삽입]을 보면, **Then** [삽입]이 비활성이고 Enter도 동작하지
   않습니다.
5. **Given** 대화상자가 열린 상태, **When** Tab을 반복해 누르면, **Then** 포커스가 대화상자 안에서만
   돕니다.
6. **Given** 커서가 `[문서](https://a.com)` 안에 있음, **When** [링크]를 누르면, **Then** 텍스트 "문서"·
   주소 `https://a.com`이 채워진 대화상자가 열리고 버튼 이름이 [수정]입니다. 주소를 `https://b.com`으로
   바꿔 [수정]을 누르면 `[문서](https://b.com)`이 되고 링크가 하나 더 생기지 않습니다.

### User Story 4 - 단축키 (Priority: P4)

작성자는 손을 키보드에서 떼지 않고 Mod-b(굵게), Mod-i(기울임) 같은 단축키로 서식을 넣습니다.
Mod는 macOS에서 Cmd, 그 외에서 Ctrl입니다.

**Why this priority**: 같은 동작을 버튼으로 이미 할 수 있으므로 편의 기능입니다.

**Independent Test**: FR-020 표의 단축키를 편집 영역에서 각각 눌러 버튼과 같은 결과가 나오는지, 한글
조합 중에는 동작하지 않는지 확인합니다.

**Acceptance Scenarios**:

1. **Given** "강조" 선택, **When** Mod-b를 누르면, **Then** [굵게] 버튼과 같은 결과가 나옵니다.
2. **Given** 한글 "가"를 조합 중, **When** Mod-b를 누르면, **Then** 조합 중인 글자가 사라지거나
   중복되지 않습니다.
3. **Given** 툴바 버튼, **When** 마우스를 올리면, **Then** 버튼 이름과 단축키(예: "굵게 (⌘B)")가
   보입니다.
4. **Given** 편집 영역 밖(툴바·상태바)에 포커스, **When** Mod-b를 누르면, **Then** 문서는 바뀌지
   않습니다.

### Edge Cases

- 같은 서식 버튼 연속 클릭: 홀수 번이면 적용, 짝수 번이면 원문입니다. `****텍스트****` 같은 중복
  문법이 생기지 않습니다.
- 선택 영역에 백틱이 있을 때 [인라인 코드]: 구분자를 백틱 2개로 늘리고 안쪽 양끝에 공백을 둬 내용이
  보존됩니다(`` `` a`b `` ``).
- 여러 줄 선택 중 일부 줄만 접두가 있을 때: 접두가 없는 줄에 추가합니다(전부 있으면 전부 해제).
- 빈 줄이 섞인 여러 줄 선택에 목록 적용: 빈 줄에는 접두를 붙이지 않습니다.
- 대화상자 주소에 공백 포함: 공백을 `%20`으로 바꿔 넣어 링크가 끊기지 않습니다.
- 대화상자를 연 채로 다른 버튼 클릭 불가: 대화상자가 떠 있는 동안 뒤 화면은 조작되지 않습니다.
- 한글 조합 중 툴바 버튼 클릭: 조합 중인 글자를 먼저 확정한 뒤 서식을 적용하고 글자가 사라지지
  않습니다.
- 브라우저 예약 단축키(탭 전환 Cmd/Ctrl-1–9 등)와 겹치는 키는 쓰지 않습니다(FR-020 표).
- 문서 맨 끝·맨 앞, 빈 문서에서 모든 버튼이 오류 없이 동작합니다.

## Requirements *(mandatory)*

### Functional Requirements

**버튼 구성**

- **FR-001**: 툴바는 버튼 18개를 아래 5개 묶음 순서로 표시해야 합니다. 묶음 사이에 구분선을 둡니다.
  H4–H6 버튼은 두지 않습니다(H4–H6 문법은 직접 입력하면 프리뷰가 렌더합니다).

  | 묶음 | 버튼 |
  |------|------|
  | 제목 | H1, H2, H3 |
  | 인라인 | 굵게, 기울임, 취소선, 인라인 코드 |
  | 삽입 | 링크, 이미지, 자동 링크 |
  | 블록 | 인용, 코드 블록, 글머리 목록, 번호 목록, 작업 목록 |
  | 구조 | 표, 구분선, 강제 줄바꿈 |

- **FR-002**: 각 버튼은 아래 표대로 동작해야 합니다. 적용 후 편집 영역에 포커스가 돌아와야 합니다.

  | 버튼 | 동작 | 선택 없을 때 | 토글 |
  |------|------|-------------|------|
  | H1 / H2 / H3 | 현재 줄들 앞에 `# ` / `## ` / `### ` | 현재 줄 | O (다른 단계면 단계만 교체) |
  | 굵게 | `**`로 감쌈 | 자리표시 텍스트 감싸고 선택 | O |
  | 기울임 | `*`로 감쌈 | 같음 | O |
  | 취소선 | `~~`로 감쌈 | 같음 | O |
  | 인라인 코드 | `` ` ``로 감쌈 (내용에 백틱 있으면 Edge Cases 규칙) | 같음 | O |
  | 링크 | 대화상자 → `[텍스트](주소)` | 텍스트 기본값 "링크 텍스트" | X |
  | 이미지 | 대화상자 → `![대체 텍스트](주소)` | 대체 텍스트 기본값 "이미지" | X |
  | 자동 링크 | `<…>`로 감쌈 | `<https://>` 넣고 `https://` 선택 | X |
  | 인용 | 현재 줄들 앞에 `> ` | 현재 줄 | O |
  | 코드 블록 | ```` ``` ```` 펜스로 감쌈 | 본문 "코드"인 펜스 블록 | X |
  | 글머리 목록 | 현재 줄들 앞에 `- ` | 현재 줄 | O (다른 목록이면 종류 교체) |
  | 번호 목록 | 현재 줄들 앞에 `1. `, `2. `, … (줄마다 1씩 증가) | 현재 줄에 `1. ` | O (같음) |
  | 작업 목록 | 현재 줄들 앞에 `- [ ] ` | 현재 줄 | O (같음) |
  | 표 | 커서 위치에 2열 표 견본 | 같음 | X |
  | 구분선 | 커서 위치에 앞뒤 빈 줄 포함 `---` | 같음 | X |
  | 강제 줄바꿈 | 선택 끝에 `\` + 줄바꿈 (선택 내용은 지우지 않음) | 커서 위치 | X |

- **FR-003**: 모든 버튼은 한글 접근 이름을 가지며 키보드로 포커스·실행할 수 있어야 합니다.
- **FR-004**: 버튼 1회 실행은 실행 취소 1회로 되돌아가야 합니다.

**토글·활성 표시 (FR-5.3)**

- **FR-005**: 인라인 토글 — 선택 영역이 해당 구분자로 감싸여 있으면(구분자가 선택 안쪽 양끝에 있든
  선택 바로 바깥에 있든) 구분자를 제거해야 합니다. 선택 없이 커서가 같은 줄의 해당 서식 범위 안에
  있으면 그 범위의 구분자를 제거하고, 커서는 같은 글자 위치(구분자 길이만큼 앞당긴 위치)에 둡니다.
  즉 버튼이 눌림으로 보이는 상태(FR-009)에서 누르면 항상 해제입니다.
- **FR-006**: 굵게(`**`)와 기울임(`*`)은 서로 다른 서식으로 판정해야 합니다. `**강조**`에서 기울임은
  해제가 아니라 추가입니다. `***강조***`에서는 각 버튼이 자기 구분자만 제거합니다.
- **FR-007**: 줄 접두 토글 — 대상 줄이 모두 같은 접두를 가지면 제거하고, 아니면 접두가 없는 줄에
  추가해야 합니다.
- **FR-008**: 제목(H1–H3)끼리, 목록(글머리·번호·작업)끼리는 서로 배타입니다. 다른 단계·종류가
  적용된 줄에 누르면 해제가 아니라 교체합니다.
- **FR-009**: 커서·선택 위치에 적용된 서식에 해당하는 토글 버튼(11개: H1–H3, 굵게, 기울임, 취소선,
  인라인 코드, 인용, 글머리·번호·작업 목록)은 눌린 상태로 보이고 보조기술에 "눌림"으로 알려야 합니다.
  커서가 움직이면 즉시 갱신합니다.

**입력 대화상자 (FR-5.4)**

- **FR-010**: [링크]는 "텍스트"·"주소" 2칸, [이미지]는 "대체 텍스트"·"주소" 2칸 대화상자를 열어야
  합니다. 첫 칸 기본값은 선택 텍스트(없으면 FR-002 기본값)입니다.
- **FR-010a**: 커서나 선택이 기존 링크(`[텍스트](주소)`) 또는 이미지(`![대체 텍스트](주소)`) 문법 안에
  있으면, 같은 종류의 버튼은 **수정 모드**로 대화상자를 열어야 합니다. 두 칸에 기존 값을 채우고 확인
  버튼 이름을 [수정]으로 바꾸며, [수정]은 그 문법 전체를 새 값으로 교체합니다. 기존 제목
  (`"title"`)이 있으면 유지합니다. 링크 안에서 [이미지]를 누르면(또는 그 반대) 수정이 아니라 새로
  넣기입니다.
- **FR-011**: 대화상자가 열리면 주소 칸에 포커스가 가야 하고, Tab 포커스는 대화상자 안에서만 돌아야
  합니다.
- **FR-012**: 주소 칸이 비어 있으면(공백만 있는 경우 포함) [삽입]과 Enter 제출이 동작하지 않아야
  합니다.
- **FR-013**: 주소의 앞뒤 공백은 제거하고 가운데 공백은 `%20`으로 바꿔 넣어야 합니다.
- **FR-014**: [삽입]·[수정] 또는 Enter는 선택 영역(수정 모드면 기존 문법 전체)을 완성된 문법으로 바꾸고, 대화상자를 닫고, 커서를 삽입한
  문법 바로 뒤에 둬야 합니다.
- **FR-015**: Esc·[취소]·대화상자 바깥 클릭은 문서를 바꾸지 않고 닫으며, 포커스와 선택을 열기 전
  상태로 되돌려야 합니다.
- **FR-016**: 대화상자가 열린 동안 뒤 화면(툴바·편집 영역·상태바)은 조작되지 않아야 합니다.

**단축키 (FR-5.5)**

- **FR-017**: 단축키는 편집 영역에 포커스가 있을 때만 동작해야 합니다.
- **FR-018**: 한글 등 IME 조합 중에는 단축키가 동작하지 않아야 하며, 조합 중 글자가 사라지거나
  중복되지 않아야 합니다.
- **FR-019**: 버튼의 툴팁은 "이름 (단축키)" 형식이어야 하고, macOS에서는 ⌘, 그 외에서는 Ctrl로
  표기합니다. 단축키가 없는 버튼은 이름만 표시합니다.
- **FR-020**: 단축키는 아래 표로 고정합니다. 브라우저 예약 키(Mod-1–9 탭 전환, Mod-t·w·n 등)는 쓰지
  않습니다.

  | 버튼 | 단축키 |
  |------|--------|
  | 굵게 | Mod-b |
  | 기울임 | Mod-i |
  | 취소선 | Mod-Shift-x |
  | 인라인 코드 | Mod-e |
  | 링크 | Mod-k |
  | H1 / H2 / H3 | Mod-Alt-1 / Mod-Alt-2 / Mod-Alt-3 |
  | 글머리 목록 | Mod-Shift-8 |
  | 번호 목록 | Mod-Shift-7 |
  | 작업 목록 | Mod-Shift-9 |

**구조**

- **FR-021**: 버튼 1개는 독립 단위 1개로 구현되고, 새 버튼 추가는 단위 1개 작성과 등록 1줄로 끝나야
  합니다(헌장 원칙 I). 편집 영역 핵심과 툴바 표시 부분은 버튼 추가 때 바뀌지 않습니다.

### Key Entities

- **툴바 버튼(Toolbar Action)**: 이름, 아이콘, 묶음, 단축키(선택), 동작, 토글 여부, 활성 판정. 18개.
- **입력 대화상자 상태(Insert Dialog)**: 종류(링크·이미지), 모드(새로 넣기·수정), 첫 칸 값, 주소 값,
  열기 전 선택 범위, 수정 대상 문법 범위(수정 모드일 때). 메모리에만 존재합니다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 18버튼 × 선택 있음/없음 36가지 경우에서 결과 문법·선택 범위가 FR-002 표와 100% 일치합니다.
- **SC-002**: 토글 대상 11버튼에서 "적용 → 다시 누름"을 실행하면 원문과 글자 하나까지 같은 문서로
  돌아오는 비율이 100%입니다.
- **SC-003**: 같은 서식 버튼을 2–10회 연속 눌렀을 때 구분자가 겹친 문법(`****`, `## ## ` 등)이 생기는
  경우가 0건입니다.
- **SC-004**: 링크 1개를 대화상자로 넣는 데 필요한 조작이 "버튼(또는 Mod-k) → 주소 입력 → Enter"
  3단계 이하입니다.
- **SC-005**: 한글 조합 중 FR-020 단축키 11개를 각각 눌렀을 때 글자 손실·중복이 0건입니다.
- **SC-006**: 마우스 없이 키보드만으로 18버튼과 대화상자 2종을 모두 실행·완료·취소할 수 있습니다.
- **SC-007**: M1 자동 테스트(제목 버튼 관련 기대값 갱신분 제외)와 렌더 conformance 테스트가 모두
  통과합니다.

## Assumptions

- **제목 단계 범위**: H1–H3만 버튼으로 제공합니다(2026-11-12 결정, requirement.md FR-5 반영). M1의
  "제목" 버튼(`## ` 고정)은 [H2]로 대체됩니다.
- **번호 목록 변경**: M1은 모든 줄에 `1. `을 넣었습니다. markdown-editor-spec.md §0("줄마다 증가")에 따라
  `1. 2. 3.`으로 바꿉니다. M1 테스트 기대값 중 번호 목록 2건을 갱신합니다.
- **링크 견본 방식 대체**: M1의 "URL 자리 선택 견본" 방식은 대화상자로 대체합니다.
- 코드 블록·표·구분선·강제 줄바꿈·자동 링크는 토글하지 않습니다(markdown-editor-spec.md §2 토글 △·X).
- 코드 블록 언어 선택 드롭다운, 이미지 파일 업로드, 링크 제목(title) 입력, 표 행·열 편집 UI는 범위
  밖입니다.
- 엔터 시 목록 자동 이어쓰기(markdown-editor-spec.md §3.4 에디터 동작)는 범위 밖입니다.
- 대화상자 주소 형식 검사(스킴 제한)는 하지 않습니다. 위험한 주소는 기존 프리뷰 정제(M1 FR-007)가
  제거합니다.
- 툴바 위치(상단 바 또는 편집 영역 위)는 M2-a(`specs/002-sidebar-layout`)가 정합니다. 이 spec은 버튼
  구성·동작만 다룹니다.
